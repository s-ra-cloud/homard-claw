Build a complete private personal AI-agent management application called **HomardClaw**.

HomardClaw is a secure, persistent, autonomous multi-agent office built on top of OpenClaw and hosted on a Replit Reserved VM. The interface should look like a charming 16-bit pixel-art office populated by small lobster agents working at desks.

The application is for one private owner. It is not intended for public distribution.

# 1. Core objective

Create a working application that lets the owner:

* Create multiple specialized AI agents.
* Customize each agent visually and behaviorally.
* Give each agent a separate identity, mission, memory, skills and workspace.
* Assign different tools, permissions and security levels to each agent.
* Run agents manually, on schedules, from webhooks or through recurring autonomous routines.
* Speak to agents using a voice interface.
* Monitor agents as animated pixel-art lobsters working in an office.
* Switch between Claude Max through Claude Code and OpenRouter models with different API prices.
* Review every action, cost, memory and tool call from a private dashboard.
* Pause or stop any agent immediately.

Use OpenClaw as the underlying multi-agent gateway, automation and tool-management layer.

# 2. Required technology

Use:

* A Replit Reserved VM for the always-running web server, worker and OpenClaw Gateway.
* TypeScript for the application.
* React for the frontend.
* Node.js for the backend.
* PostgreSQL as the durable source of truth.
* Replit Object Storage for durable files, agent workspaces, generated artifacts and backups.
* WebSockets or Server-Sent Events for live task and animation updates.
* OpenClaw for agent routing, sessions, tools, schedules and agent workspaces.
* Claude Code or Claude Agent SDK for Claude Max execution.
* OpenRouter for pay-per-token model execution.
* A process supervisor that starts and monitors the web server, task worker and OpenClaw Gateway.
* A durable PostgreSQL-backed task queue that survives application restarts.

Use the latest stable compatible versions, verify them against the current official documentation, pin them in the lockfile and document the selected versions.

Do not rely on the deployment filesystem for persistent data. Replit deployment files may be replaced during deployment or restart. Hydrate required agent configuration and workspace files from durable storage when a worker starts.

# 3. Provider switch

Create a prominent provider selector in the main interface:

* **Claude Max**
* **OpenRouter**

The owner must be able to set:

* A global default provider.
* A provider for each individual agent.
* A temporary provider override before launching a task.
* A default model for each OpenRouter agent.
* Optional fallback models.
* Maximum cost per task, per day and per month.

## Claude Max mode

Use the official Claude Code authentication path.

The owner will generate a long-lived token separately with:

```bash
claude setup-token
```

Read it only from this Replit Secret:

```text
CLAUDE_CODE_OAUTH_TOKEN
```

Use Claude Agent SDK directly where possible. Alternatively, execute Claude Code in non-interactive mode using `claude -p`.

Requirements:

* Never expose the OAuth token to the browser.
* Never print it in logs.
* Never store it in PostgreSQL.
* Never place it inside agent memory or workspace files.
* Pass it only to the isolated Claude Code process that needs it.
* Do not set or use `ANTHROPIC_API_KEY` in Claude Max mode.
* Do not silently switch to paid Anthropic API usage.
* If the Claude Max quota is exhausted, pause the task and clearly report that the subscription limit was reached.
* Display subscription usage information when it can be obtained reliably.
* Display “usage unavailable” when exact quota information cannot be retrieved.
* Never invent quota figures.
* Include a provider health test in Settings.

## OpenRouter mode

Read the OpenRouter credential only from:

```text
OPENROUTER_API_KEY
```

Retrieve the current model catalogue and pricing dynamically from OpenRouter. Do not hard-code prices.

For every model, show:

* Model name.
* Provider.
* Context window.
* Input price.
* Output price.
* Supported capabilities.
* Estimated cost before starting a task.
* Actual cost after completion.
* Total monthly usage.

Allow filtering models by:

* Price.
* Context length.
* Reasoning capability.
* Speed.
* Tool support.
* Vision support.
* Provider.

Never fall back from Claude Max to a paid OpenRouter model unless the owner has explicitly enabled that fallback.

# 4. Pixel-art office interface

Create an original 16-bit pixel-art visual identity. Do not use Nintendo, commercial game or copyrighted character assets.

The main dashboard should show a pixel-art lobster office. Each AI agent is represented by a small lobster employee at a workstation.

Each lobster’s animation must reflect the agent’s real state:

* Sleeping or relaxing: idle.
* Looking through papers: retrieving memory.
* Typing at a computer: executing a task.
* Reading a book: researching.
* Walking to another desk: delegating to another agent.
* Holding a telephone: waiting for owner input.
* Flashing red desk light: approval required.
* Smoke or warning symbol: error.
* Raising both claws: task completed.
* Spinning hourglass: queued or rate-limited.

The office must include:

* Individual desks.
* Agent nameplates.
* A mission board.
* A cost and quota display.
* An approvals desk.
* A memory archive room.
* A security control room.
* A large emergency stop button.
* A microphone button for voice mode.

Clicking a lobster opens that agent’s profile, current task, recent memories, permissions, schedule and conversation.

Use crisp pixel rendering with `image-rendering: pixelated`. Keep text readable and make the application responsive on desktop, tablet and mobile.

* Its own memory settings.

# 8. Sandboxing and security

Security rules must be enforced in backend code and at the tool-execution layer. Prompt instructions alone are insufficient.

Enable sandboxing by default.

Before implementing execution:

1. Detect which OpenClaw sandbox backends are supported on the Replit Reserved VM.
2. Test the selected backend.
3. If Docker or Podman is unavailable, use another supported OpenClaw sandbox backend or a remote sandbox provider.
4. Never silently disable sandboxing.
5. Clearly mark any agent running with host access.

Security requirements:

* Private Replit deployment.
* Single-owner authentication.
* Secure session cookies.
* CSRF protection.
* Rate limiting.
* Server-side authorization on every endpoint.
* Secrets stored only in Replit Secrets.
* No secrets in frontend bundles.
* No secrets in logs.
* No secrets accessible to agents.
* Separate workspace for every agent.
* Network allowlists.
* Tool allowlists.
* Resource limits.
* Protection against command injection.
* Protection against path traversal.
* Protection against server-side request forgery.
* Treat websites, emails, files and tool results as untrusted input.
* Human approval for sending, publishing, deleting, purchasing, changing credentials or modifying important external data.
* Append-only audit log.
* Per-agent pause button.
* Global emergency stop.
* Automatic suspension after repeated failures.
* Approval requests that expire.
* Daily database backups.
* Configuration rollback.
* No unrestricted “yolo” mode in the UI.

Use a credential-injection proxy when external tools require secrets, so agent processes never receive raw credentials.
